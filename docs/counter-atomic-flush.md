# 计数聚合桶原子刷写

`CounterAggregationConsumer` 每轮枚举 `agg:v1:*` 的字段，然后对每个字段执行
`redis/flush-counter-field.lua`。Java 只传桶 key、总计数 key 和字段编号，不读取或传递增量快照。

脚本在一次执行中完成：

1. 读取字段当前增量；字段不存在则退出。
2. 校验字段、整数精度、总计数结构及 32 位无符号上界，在内存中计算新值。
3. 更新 `cnt:v1:{entityType}:{entityId}` 的对应 4 字节槽位。
4. 删除已处理字段；Redis 会在最后一个字段被删除时自动删除 Hash。

脚本期间其他客户端无法插入命令。后到的 `HINCRBY` 会重新创建字段，下一轮再处理。
多个实例同时刷同一字段时，后执行的实例只能读取尚未处理的增量。若脚本执行成功但客户端
没有收到响应，重试也不会重复应用已删除的增量。零增量直接清理；负值仍沿用原逻辑将总数
下限限制为 0。异常格式或溢出会保留桶内增量并记录错误，修复后可以重试。

Lua 运行错误不会回滚已写入的数据，因此结构校验和编码全部放在写入前。这解决的是应用
并发和两次调用之间的故障窗口，不代表独立的磁盘刷盘保证。

## 验证

集成测试需要一个独立、空闲的 Redis 实例（建议与部署一致使用 Redis 7.4）。不要使用业务
实例：消费者会扫描 `agg:v1:*`。测试只删除自身生成的 UUID 测试 key，不执行 FLUSHDB。

例如先在独立终端启动临时 Redis（关闭持久化，测试结束后停止）：

```sh
redis-server --bind 127.0.0.1 --port 16379 --save "" --appendonly no
```

然后在后端仓库执行（PowerShell 中给 `-D` 参数加引号）：

```sh
mvn "-Dcounter.test.redis.port=16379" test
```

可通过 `-Dcounter.test.redis.host=...` 指定测试地址。不提供端口时，真实 Redis 集成测试
默认跳过，其余单元测试照常执行。用例覆盖重复刷写、并发刷写、并发写入、后续新增量、
零/负增量、字段隔离、二进制槽位保留、非法结构和溢出保护。

## 范围与限制

- Kafka 消费重投的幂等、位图更新与发事件的一致性、位图重建与刷写的协调仍需单独处理。
- 当前仍通过 `KEYS` 枚举聚合桶，大规模 key 空间需要另行改为增量扫描或待处理索引。
- 当前部署为单实例 Redis。脚本涉及两个 key；迁移 Redis Cluster 时必须先调整 key 的
  hash tag，确保同一实体的聚合桶和总计数处于同一 slot。
- 总计数保持现有 5 × 4 字节格式；不需要前端或接口调整，也不需要迁移现有聚合桶。
